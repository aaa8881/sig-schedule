# 디스코드 작업일지

사용자가 그날 작업 종료를 알릴 때만 이 문서를 읽는다. 평소 기록 입력·사이트 배포·정해진 시각만으로 보내지 않는다. 기록 갱신 규칙은 tracking.md를 따른다. 별도 웹 담당 호출은 필요 없다.

## 첫 연결과 승인

1. 로컬 `.env.discord`에 `DISCORD_WEBHOOK_URL=`을 설정한다. 필요하면 `DISCORD_THREAD_ID=`를 사용한다. 이 파일은 .gitignore의 .env.*로 제외된다. URL은 읽을 때 내용 출력하지 않고 스크립트가 실행 시 읽는다. 공개 JSON·문서·브라우저·GitHub에 URL을 넣지 않는다. 전송 대상 채널명은 사람에게 확인한다. 포럼 채널은 기존 스레드 ID를 지정한다.
2. 오늘 실제 활동을 먼저 기록한다. 계획을 완료한 일로 바꾸지 않는다. `node scripts/discord-diary.cjs --preview --date YYYY-MM-DD`로 Discord embeds JSON 미리보기를 생성한다. 작업별 내용, 다음 할 일, 기록된 운동/생각이 포함된다. 원문 source/corrections는 보내지 않는다.
3. 첫 전송 전 실제 일지 내용과 채널을 사용자에게 보여주고 명시적 확인을 기다린다. 아직 URL이나 일지가 없으면 필요한 것만 요청하고 전송하지 않는다. 없는 활동을 샘플로 전송하지 않는다.
4. 사용자가 승인한 정확한 미리보기의 approvalHash로 `node scripts/discord-diary.cjs --send --date YYYY-MM-DD --approve-first HASH`를 실행한다. 성공 응답과 messageId를 확인한다. 실패하면 승인된 시험이 끝났다고 보고하지 않는다.
5. 시험 메시지를 보고 사용자가 앞으로 이 방식이 괜찮다고 명시하면 `node scripts/discord-diary.cjs --approve-auto`를 실행한다. 최초 시험 승인만으로 계속 자동 전송 승인까지 추정하지 않는다.

## 이후 하루 마감

- '오늘 작업 끝/오늘 마감하자/오늘 일지 보내줘'가 전송 트리거다. 반복 승인 완료 후에는 해당 마감 요청을 받아 데이터 갱신·검증, `--preview --quiet`로 전송 데이터 생성, `--send`까지 수행하고 결과만 보고한다. 미리보기 JSON을 매번 대화나 도구 출력에 넣을 필요는 없다.
- 최초 합의 범위 밖의 채널·웹훅으로 바뀌면 다시 시험 승인한다. 건강·생각을 빼달라고 요청하면 생성기 또는 출력 규칙을 조정하고 새 내용을 검토한다.
- 그날 완료된 일과 실제 activity만 작업 실적으로 보낸다. 당일 새 할 일/활동에 연결된 미완료 작업은 '다음 할 일'로 분리한다. 날짜는 Asia/Seoul. 여러 차례 마감 요청 시 동일 내용은 건너뛰고 내용이 바뀌었으면 같은 메시지를 수정한다.
- 한 메시지의 embed 총 6,000자/필드 25개 등 Discord 제한을 검증한다. 넘치면 AI가 원본 활동 기록을 잃지 않도록 요약을 줄인다. 의미 없이 잘라 보내지 않는다. Markdown 표·HTML은 사용하지 않고 간단한 목록/줄바꿈과 embeds를 사용한다. 사용자 텍스트의 Markdown 특수문자는 escape하고 allowed_mentions.parse=[]로 알림 멘션을 막는다.
- 전송 이력·미리보기·승인 상태는 `.local/discord/`에만 저장한다. 파일 복사나 새로운 PC에서는 다시 설정해야 한다. GitHub Actions나 공개 웹페이지에서 자동 전송하지 않는다.
- timeout/연결 끊김/pending 상태는 성공 여부가 불확실하므로 자동 재전송하지 않는다. 실제 채널 메시지를 확인하고 기존 messageId를 이력에 연결한 뒤 갱신한다. HTTP 429는 안내한 시간 이후 재시도한다. 원문 네트워크 오류나 전체 URL을 출력하지 않는다.
- '디스코드 자동 전송 그만' 요청은 `--disable-auto`. 상태 확인은 `--status`.

이 동작은 사용자가 마감 메시지를 준 시점에 AI가 수행하는 흐름이다. 작업 종료를 감지하는 상시 프로세스나 예약 자동화가 아니다.
