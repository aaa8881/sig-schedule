# 기록 담당

읽을 파일: 이 문서와 data/journal.json. 수정 범위: data/journal.json. 기존 스키마로 표현할 수 없는 새 기능 요청은 웹 작업으로 분리한다. 웹 담당을 매번 호출하지 않는다.

## 초기 구성 (2026-10-04)

아래는 처음 등록한 상태의 참고 기록이다. 이후 현재 상태는 항상 data/journal.json을 따른다. 이 초기값으로 현재 기록을 되돌리지 않는다.

- 개인 작업: 베어타운, 마인팜. 공부는 아직 프로젝트 없음.
- 베어타운: Lands·Upgradable Hopper·Chest Protect 업데이트 진행 중.
- 마인팜: 성자와 노드 기획 할 일. 완료 활동으로 등록하지 않음.
- 운동: 매일 짐 가기. 달성 기록 없음.
- 생각 없음. 첫 날짜별 기록은 실제 완료가 아닌 초기 계획.
- 하위 버전/프로젝트, 미분류 기타 작업, 프로젝트별 기타 메모 지원.
- '성자와 노드 기획'은 사용자 음성 입력 표기를 보존함. '렌즈'는 사용자의 땅 관리 설명에 따라 Lands로 해석해 정정. 한국어 발음/축약어는 aliases로 기존 작업에 연결.

# 시그일정 기록 갱신 지침

이 폴더는 Minecraft 서버 설정과 무관한 별도 웹사이트다. 서버 설정, DB, 로그를 읽거나 수정할 필요가 없다. 사이트의 유일한 기록 원본은 `data/journal.json`이다. GitHub 공개용이므로 비밀번호, 토큰, 개인 연락처와 플러그인 설정을 넣지 않는다.

사용자가 오늘 한 일을 말하고 사이트에 반영해 달라고 하면, 다음 절차를 한 번에 수행한다.

1. 현재 기록을 읽고 기존 프로젝트·하위 프로젝트·할 일을 찾아 연결한다. 새 목표를 기존 목표와 중복 생성하지 않는다. 카테고리는 개인 작업·공부·운동이며 사용자가 요청하면 확장할 수 있다.
2. 날짜는 Asia/Seoul 기준으로 해석한다. 명시한 활동 날짜가 우선이다. 계획을 실제 활동으로, 진행을 완료로 바꾸지 않는다. 운동도 방문했다고 명시할 때만 해당 날짜의 checkin을 추가한다.
3. 큰 프로젝트는 `projects`, 버전/작은 프로젝트는 그 안의 `groups`에 둔다. `type`은 `version` 또는 `initiative`. 버전·추석·Retention Improvement는 지원할 수 있는 구조의 예시이며 사용자가 시작하라고 하지 않았다면 실제 프로젝트를 만들지 않는다.
4. 할 일은 `tasks`, 분류 없는 작은 작업은 `groupId`를 생략한다. 기타 메모는 프로젝트 `notes`에 `{date, body}`로 저장한다. 생각·어록은 `thoughts`에 `{id,date,type,body,tags,projectId?}`로 저장한다.
5. 날짜별 기록은 `entries`에 `{id,date,kind,title,body,projectIds,taskIds,source}`로 추가한다. `kind`는 계획 `plan` 또는 실제 작업 `activity`. `source`에는 사용자 입력 중 관련 원문을 보존한다. 앞서 등록한 동일 활동을 다시 말하면 중복 추가하지 말고 보완한다.
6. 상태는 `todo`, `doing`, `done`. 완료에는 `completedAt`을 추가한다. 이전 활동은 남기고 잘못 기록된 경우 해당 기록을 명시적으로 정정한다. 진행률은 등록한 할 일의 완료 비율이며 프로젝트 전체 완료율로 표현하지 않는다.
7. 기록만 수정할 때는 `node scripts/validate.cjs`만 실행한다. 웹 코드·스타일·배포 지침을 읽거나 브라우저 전체 검증을 반복하지 않는다. push 후 자동 배포 성공 및 공개 data/journal.json에서 수정한 항목만 확인한다. 검증·배포 오류가 발생하면 관련된 파일만 추가로 읽는다.
8. GitHub 원격 연결과 사용자 인증이 되어 있고 사용자가 사이트 반영까지 요청한 경우 변경을 commit/push한다. Pages 배포 성공까지 확인한다. push 성공만으로 공개 완료라고 보고하지 않는다. 토큰을 파일에 저장하거나 대화에 출력하지 않는다.
9. 완료 보고에는 반영한 기록, 실제 배포 결과, 해석이 불확실한 표기만 간결하게 적는다. '성자와 노드 기획'은 아직 정확한 표기가 미확인이다. 사용자 정정 없이 바꾸지 않는다. 사용자 설명의 땅 관리 플러그인은 Lands로 해석하여 표기 정정했고, Upgradable Hopper와 Chest Protect는 영어 표기를 사용한다.

## 음성 입력과 정정

- 입력 순서와 형식을 요구하지 않는다. 프로젝트·작업·상태·다음 할 일·운동·생각을 자유롭게 말하면 분리한다. 완료/진행/계획을 구별할 수 없으면 완료를 추측하지 않는다.
- tasks의 `aliases`를 기존 작업과 연결할 때 참고한다. '렌즈/랜즈/땅 관리 플러그인'은 현재 베어타운의 Lands, '업그레이더블 호퍼'는 Upgradable Hopper, '체스트 프로텍트/상자 보호'는 Chest Protect다. '호퍼'처럼 일반적인 단어는 프로젝트와 작업 문맥까지 일치할 때만 연결한다. 여러 작업과 일치하면 필요한 부분만 질문하고 나머지는 반영한다.
- '아까 호퍼 완료라고 했는데 테스트만 끝났어', '그건 어제 한 일이야', '이 생각은 마인팜으로 옮겨줘' 같은 정정도 처리한다. 기존 ID를 유지하고 관련 날짜별 기록과 할 일을 함께 수정한다. 실제 수정 근거는 entries의 `corrections`에 `{date,source,summary}`로 남길 수 있다. 단순 표기 정정은 새 완료 활동으로 만들지 않는다.
- '정리만 해줘'면 저장·push하지 않고 정리 결과만 보여준다. '시그일정에 반영해줘/기록해줘'면 검증·push·배포 확인까지 수행한다. 매번 별도 승인을 요구하지 않는다.
- 반영 후에는 완료/진행/할 일/운동/생각 중 해당 항목만 짧게 보여준다. 이 요약을 읽고 사용자가 이어서 말로 정정할 수 있게 한다.

## 하루 마감과 디스코드

사용자가 '오늘 작업 끝/오늘 마감/오늘 일지 보내줘'라고 할 때만 `workflows/discord.md`를 추가로 읽는다. 평소에는 기록만 갱신한다. 첫 시험 전송과 그 이후 자동 전송 활성화는 사용자 확인을 각각 받은 뒤 수행한다. 웹훅 URL·전송 이력·승인 상태는 로컬 비공개 파일이며 사이트 데이터에 포함하지 않는다.

개인 기록 수정은 AI를 통한 GitHub 갱신으로 수행한다. 공개 페이지에는 방문자가 원본 기록을 수정하는 기능이나 인증 토큰을 넣지 않는다. 브라우저 localStorage를 공유 기록의 원본으로 사용하지 않는다.
